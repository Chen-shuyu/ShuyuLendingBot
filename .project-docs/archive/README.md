>
> **現在的狀態看 [../STATUS.md](../STATUS.md)，不要從這裡找。**

## 為什麼要有這個資料夾

2026-08-23 做了一次全文件對齊盤查，量到的數字是：

- 依專案規則，每個新對話開場要讀 PLAN＋PROGRESS＋DECISIONS＋TASKS
  = **6,528 行、21.6 萬字**
- PLAN.md 裡疊了 **6 個「目前所在位置」**，要讀完全部才知道哪個是現在
- TASKS.md 有個叫「🔴 下一步・最高優先」的區塊，302 行，內容全是三週前的事
- 同一件事（例如 D041）在五份文件各寫一遍，**同一句比喻逐字出現在 3 個檔案**

> **問題不是「太長」，是「分不出哪一段是現在」。**
> 缺漏會讓人去問；矛盾會讓人挑一個相信，而且常挑到錯的那個。

所以改成三層：**現在（STATUS）／為什麼（DECISIONS、ARCHITECTURE）／
當時發生什麼（PROGRESS、CHANGELOG、本資料夾）**。

## 刻意**不**搬進來的

| 檔案 | 為什麼留在主資料夾 |

| [../DECISIONS.md](../DECISIONS.md) | **程式碼註解裡有 141 處 `見 D0xx`**。拆檔會把這 141 個指標指向不存在的地方。ADR 是唯一「完整性比長度重要」的文件——它不該瘦身，該加索引（已加） |

> 參考留在主資料夾，歷史才搬進來。

## ⚠ 不要跟專案根目錄的 `archive/` 搞混

專案裡有**兩個**叫 archive 的資料夾，內容完全不同：

| 路徑 | 放什麼 |
|---|---|
| **`.project-docs/archive/`**（本資料夾） | 從六份主文件搬出來的歷史段落 |
| `archive/`（專案根目錄） | 專案最早期的規劃書 `PRD.md`、`SHUYU_PROJECT_PLAN.md`，2026-07 就歸檔了（見 D008） |

根目錄那份是**專案開始前**的文件，本資料夾是**專案進行中**被主檔汰換下來的段落。

## 規則

1. **只搬不刪。** 任何搬移都要在原位置留下指標，並在上面的表格補一行
2. **搬移不改內容。** 歷史紀錄的價值在於它是當時寫的，事後潤飾等於偽造
3. **git 是最後一道保險**：就算表格漏了一行，`git log --follow` 也找得回來
